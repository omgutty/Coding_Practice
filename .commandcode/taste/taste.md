# Taste

- For coding-interview practice questions, gives multiple solution options per problem rather than wanting a single best answer — expects the "obvious" solution to be shown but also wants alternatives (different techniques like filter/indexOf, reduce, Set, loops) with their trade-offs and complexity notes, and will keep asking for "other options" to collect more variants. Confidence: 0.8
- Asks for explanations of individual lines/snippets in their practice files while studying for interviews ("explain me this line", "explain me this, ? :") — wants a plain-language breakdown of what each part does, backed by a concrete worked example and interview-relevant gotchas (e.g., `.includes()` being case-sensitive, ternary readability and nested-ternary pitfalls). Confidence: 0.7
- Asks the assistant to write detailed explanatory comments directly into their practice files after explaining code ("add proper detailed comment", "explain and update the file") — wants multi-line comment blocks covering line-by-line breakdown, a worked walkthrough, and complexity notes, not just conversational explanation, and expects the code in the file to actually work (bugs fixed, verified to run). Confidence: 0.8
- Uses very terse, bare prompts in practice files to request help ("solution", "answer", "solution for this", "explain this code") rather than framing full questions — points at selected lines of their practice.js and expects a full worked answer with options, without the user spelling out the intent. Confidence: 0.6
